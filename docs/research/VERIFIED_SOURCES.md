### Historical ERC-20 state calls

Retrieved 2026-08-11: [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) defines canonical
block-hash parameters for state methods; the [Alchemy BNB `eth_call`
reference](https://www.alchemy.com/docs/chains/bnb-smart-chain/bnb-smart-chain-api-endpoints/eth-call)
documents read-only contract calls, and [Alchemy archive-data
guidance](https://www.alchemy.com/docs/what-is-archive-data-on-ethereum) explains why historical
state availability differs from ordinary full-node retention. ZeroTrace therefore sends
`blockHash` plus `requireCanonical=true`, compares exact block/state results across sources, and
fails closed on pruned or unavailable state. A provider error such as `missing trie node` is never
interpreted as unchanged supply.

### Current-state Snapshot contracts

- [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/) defines named block tags,
  canonical hex quantity/data encoding, and the block, balance, and code methods used by the EVM
  adapter. `eth_getBlockByNumber` returns the block hash and `parentHash`. ZeroTrace defaults named
  EVM networks to `finalized`, records the selected tag, and binds the parent hash to the Snapshot.
- [Esplora's API contract](https://github.com/Blockstream/esplora/blob/master/API.md) exposes
  `/blocks/tip/height`, `/block-height/:height`, and `/block/:hash`; the block record includes its
  identity, height, and `previousblockhash`. ZeroTrace validates all three instead of independently
  sampling tip height and tip hash.
- [Bitcoin Core `getblockheader`](https://bitcoincore.org/en/doc/30.0.0/rpc/blockchain/getblockheader/)
  exposes `previousblockhash` and reports `confirmations: -1` when a block is not on the main chain.
  This is the authoritative target for future Core/Esplora reorg reconciliation; the current adapter
  implements Esplora parent-history continuity but does not yet call Core.
- Solana's official [`getSlot`](https://solana.com/docs/rpc/http/getslot),
  [`getBlock`](https://solana.com/docs/rpc/http/getblock), and
  [`getAccountInfo`](https://solana.com/docs/rpc/http/getaccountinfo) contracts distinguish a
  slot-specific blockhash from a recent transaction blockhash and provide the account context slot.
  The official [confirmed-block JSON structure](https://solana.com/docs/rpc/json-structures)
  includes `parentSlot` and `previousBlockhash`. ZeroTrace binds those fields to the anchor, enforces
  the account-context distinction, and preserves explicit null account state.

### Anchor reconciliation source policy

The sources above define block and parent identity; different URLs or hostnames alone never prove
provider organizational independence. General anchor health therefore retains
`sourceIndependence=Unknown(NOT_QUERIED)`.

The Flap/Pancake V2 reconciliation path additionally uses the versioned
`source-operator-registry-v1`. Its BSC entries map `bnb-mainnet.g.alchemy.com` to Alchemy and the
documented `bsc-dataseed*.bnbchain.org` hosts to BNB Chain, with an Evidence node for the registry
and each official-document attestation. It returns verified independence only when every source is
registered and at least two operator IDs are present. Two BNB Chain endpoints remain same-operator;
an unknown hostname remains inconclusive. This scoped operator result does not prove archive
retention, outage independence, or forced-reorg behavior.

## Decisions produced by research

1. Reuse protocol decoders and read APIs behind adapters; do not duplicate mature parsing.
2. Keep the canonical data/evidence model independent of any provider or platform schema.
3. Keep AGPL/GPL systems outside the Apache core unless an explicit review approves another model.
4. Treat missing/unclear licensing as a hard reuse boundary.
5. Public endpoints are convenient smoke-test inputs, not production evidence infrastructure.
6. Discover deployments and mechanism versions at the target snapshot; do not hard-code “current”
   behavior into historical analysis.
7. GMGN remains an optional observation source, not a launchpad classifier or identity oracle.

## Open research gates

- authoritative Four.meme contract deployment/version registry and ABI licensing;
- FomoWell canister IDs, Candid interfaces, ledger relationships, and historical versioning;
- Moonshot current deployment registry for each supported ledger;
- Meteora DBC repository licensing and compatible decoder boundary;
- production terms/quotas for every hosted provider;
- independent archive and explorer sources for reproducible real-chain fixtures.
