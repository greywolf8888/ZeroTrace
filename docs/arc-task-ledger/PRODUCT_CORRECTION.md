# Arc Task Ledger v1.2.0 产品闭环

2026-10-06。沿用现有 ArcBounty 主网登记部署、资金规则和 PostgreSQL，专用分支 `agent/arc-task-ledger-v1`。本轮的当前提交、真实线上执行和最终状态见 `validation/product-v120/`；下列功能描述不代替实际验收收据。

用户从首页输入任务编号、`https://arcbounty.app/bounty/<jobId>` 或完整地址。地址可按发布者／工作者及业务、资金状态筛选，分页在数据库内执行。任务路径保留链、部署、任务编号和固定 `snapshotRunId`；过期返回 410，用户明确选择新查询后才换快照。首页例子来自 API 当前已核验任务，未写死任务编号。

详情第一屏展示同一 `atl-settlement-result-v1`：面值、已观察工作者报酬、费用、退款和具体义务未清偿额。账户总待领取额不分配给任务，保证金不算奖励，未知不转零。资金分配、义务、提现批次和 Gas 证据可以展开；Gas 只按交易显示，不从报酬中扣减，不按任务重复汇总。单来源和历史缺口保持可见。

报告路径 `/tasks/5042/<adapter>/<jobId>/report?snapshotRunId=<run>` 与详情使用同一结果和证据，可打印为 PDF 或导出 JSON。`/consumer?jobId=<jobId>&snapshotRunId=<run>` 通过真实 HTTP 使用同一个结果卡，不重新解释资金；HTTP 错误与证据不足分别降级。例子代码见 `examples/arc-task-ledger/consumer.ts`。报告不是官方审计证书，分享不接受或上传私密说明。

“重新加载已采集结果”只读数据库。“申请有限补证”明确使用 POST 创建数据库控制记录，链上仍只读：仅已登记部署的已采集任务，无自定义 URL、合约或扫描区间；每 IP 每小时 6 次，每任务每小时 1 个新申请，全局最多 20 个当前版本待办，单申请最多 200000 区块，单轮最多 2000。相同任务、快照、模型申请幂等，退休版本不被新 worker 消费。

复用已有 cron 和数据库。最新变化、请求补证和旧历史回填有各自水位和预算，原始回执、区间记录、水位和请求进度在同一事务内落盘。最新/补证单轮各最多 2000 区块。已最终确认的定点区块先验证摘要，再复用原始观察与来源；缓存不提升全历史或多来源覆盖。新版模型为 `atl-v1.2.0`，旧快照和证据不改写。

API 查询账号继续只读；新增 `atl_evidence_requester` 仅能读取／插入补证申请表，不能插入任务投影或原始证据。迁移版本为 5。Northflank 管理 Token 不进入应用、构建或页面。资源规格、实例和存储配额保持现状，新增支出授权 0。

本地特殊结算与新任务产生使用隔离合成链并显式标注；不冒充主网观察。主网是否出现新任务和稀有结算由当次实际记录说明。正式取证仍因历史和单来源覆盖不足关闭，但不妨碍已经成立的局部资金事实查询。未联系上游、未申请奖金、未取得真人评审或采用证明。

本轮发现 Circle／Blockdaemon 登记公共来源未返回部署回执，旧 cron 停止发布并保留旧快照。依据 [Arc 官方连接文档](https://docs.arc.io/arc/references/connect-to-arc) 登记公共 dRPC，经真实 5042 链身份、当前部署、四个定点归档区块核验后选为默认采集来源。任务 #18 原始历史回执摘要与旧观察一致；此有限比较不提升全来源一致性。旧观察保留自身来源和时间，运行时来源标签由登记地址确定，不沿用错误的 Circle 标签。来源资格可能变化，每轮仍重新验证，失败不改为零或成功。

原资金回归和新增产品回归均保留。桌面和手机浏览器套件分别启动隔离测试服务，以免同一测试进程连续累计请求触发生产查询限额；生产限额没有放宽。命令记录只公开脱敏摘要与源码对应关系，私有运行目录不公开。
