# Arc 界面修复：计划、复用与边界

用户本轮明确要求界面默认英文，并将中英切换限定为统一、完整的产品界面设置；这一指令优先于早期中文默认约定。该变更仅用于 Arc 网页，不改变 ZeroTrace 其他业务域的语言或数据权威。

## 执行计划与已有方案

1. 统一语言。使用 React Context 在应用根提供语言，沿用现有 React，持久化到浏览器偏好；初次访问、无效偏好及存储不可用均为英文。核验、任务详情、旧报告、资金工作台、独立消费者、状态说明及分享预览使用同一设置。协议标识、地址、哈希与原件正文不翻译。
2. 修复状态边界。条件编辑保持旧报告不可覆盖并显示草稿提示；任务重新查询先清除旧可选资金段；请求处理中保留请求编号，状态查询不重新读取链。同输入重试复用请求键，新尝试明确换键。
3. 重排报告。复用现有精确 USDC 格式化器与报告结构，摘要优先，显示冻结来源、收款总额和净变化；金额核对项显示 USDC 单位。普通报告和完整分享预览使用同一组件。
4. 对齐权限。复用现有 ownership/publication 表与会话，不新增登录或生产记录系统。列表只返回当前会话最近20个原件版本；报告的管理权限及公开范围由服务端返回。复制链接不改变权限，公开确认保持原流程。
5. 改善手机和辅助访问。使用原资金清单作为手机表示，桌面图保持可读字号；原件使用浏览器原生 dialog，支持关闭和焦点边界。HTML 日期控件沿用浏览器；应用按 UTC 解释时间。打印保留核对内容，动效尊重减少动态效果偏好。
6. 验证、发布。分别执行语言/金额单元、真实数据库权限、桌面与手机浏览器、旧任务/分页/导出回归和构建检查。仅更新已授权的既有云端资源，固定部署版本，不改数据库和费用规格。

采用的标准能力：[React Context](https://react.dev/reference/react/useContext)、[浏览器 dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog)、[Intl 日期格式](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)、[减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)。未新增翻译服务、图形库、身份系统或结算数据权威。

## 可复查的行为变化

- 首页只保留交易/ArcBounty 核验入口，任务列表由顶栏进入；旧任务和消费者入口继续可用。
- 草稿金额改变时，原 MATCHED 报告保持固定，但明确不适用于新条件。按当前条件核对才生成新报告。
- 条件来源区分用户填写与登记任务，保留任务编号和快照。确认收款不等于最终保留资金，净变化单列。
- 公开访问者只能读取、导出或按公开事实建立自己的条件；不能管理原所有者报告。权限信息不进入固定报告哈希。
- CHAIN 等无资金段的核对项可打开交易和来源原件；资金段原件包含规范事件及其镜像事件。
- 导出、打印、建立新版本位于报告金额附近；逐项检查可以展开，打印始终包含检查内容。
- 手填地址、金额与区间错误在字段附近显示；原始服务错误留在明确标识的展开区，避免主界面跨语言混杂。

## 审计问题覆盖与后续单位

本轮落实 UI01—UI26 的主要修复，UI21 按用户新指令改为英文默认。复用方案已列在上述计划中；数据库记录、精度规则、镜像归一化、离线复算和现有图形不另建实现。实现覆盖不等于逐条主网验收：字段、语言、状态、打印和权限由针对性浏览器/真实数据库检查证明；旧任务金额、分页与原件由既有回归证明。

- UI27：保留完整金额和证据标识，已改善换行与层级；所有长地址的一键复制/短显尚未统一。
- UI28：示例由已公开固定报告索引提供，并说明事实范围；按真实报告自动生成原生/镜像场景标题尚未实现。
- UI29：金额、报告和选择联动及减少动态效果已落实；尚未逐帧对照参考图验收全部动态细节。
