# 架构决策

## ADR-001：工作分支命名冲突

执行提示词要求 `codex/zerotrace-product-closure-bsc-v1`，仓库根 `AGENTS.md` 要求唯一分支 `agent/terminal-market-structure-v1`。采用更贴近仓库且更严格的后者；最新 `main` 通过非快进历史合并进入该分支，不改写旧提交。

## ADR-002：BSC V1 是产品焦点，不删除其他一级架构域

交付按 BSC Token 案件依赖顺序推进，但 EVM、Bitcoin、Solana、Entity Resolution、Launchpad、RV、Evidence、Scenario 与 UI 保持一级领域边界。UI 一级导航可以按用户任务收敛，代码架构域不得被删除或混并。

## ADR-003：无法证明精确时降级能力，不改测试迎合实现

V3 虚拟储备与多场所贪心分别标记为研究近似；只有 pinned archive fork、bytecode 验证和 replay hash 一致时 exact VM 才可 Ready。该决策保持 Unknown/Unsupported/PARTIAL，不以数值或文案伪装完成。

## ADR-004：正式取证必须 durable/fail closed

Research 模式可使用进程内设施便于本地探索；ADMISSIBLE/FORENSIC 必须有持久队列、报告库、原始 artifacts 与 replay 条件。缺任一关键设施时返回不可用/阻断，不静默降级。

## ADR-005：合并条件

用户要求完成全部任务后合并并只保留 main；仓库规则禁止任何终局 gate 未通过时合并。两者合并解释为：全部 G0–G14 PASS 后执行 `--no-ff` 合并并删除短期分支；否则保留分支与提交，准确报告阻断。
