# 已知缺陷与反例

## 本轮已复现并修复

1. Windows Playwright 默认 12 workers：42 个测试中 33 个在 teardown 超时。反例为相同代码 `--workers=2` 全部通过；修复后连续执行桌面 21/21 与全量 42/42。
2. `A Must-Link B`、`B Must-Link C`、`A Cannot-Link C`：旧实现可能完成传递合并；现 fail closed。
3. 未计算全盘退出 U：旧物化路径传入字符串 0；现保留 typed Unknown。
4. V3 虚拟储备：旧命名暗示执行；现无完整 VM 证据时只能研究近似。
5. 多 venue 贪心：旧 crate 命名暗示 optimizer；现多 venue 明确研究近似。

## 尚未解决

- 正式 HTTP handler 仍同步执行，durable worker 不是唯一生产主链。
- 生产 worker 内存在三枚 Token 的 creation transaction 硬编码映射。
- JobQueue 缺 cancel、retry、heartbeat 与阶段结构化 schema。
- 任意 BSC Token 的起源到 finalized coverage 尚未闭合。
- V3 跨 tick、重复池和共享流动性全局优化未实现。
- UI 仍是十四个一级技术入口；主路径存在默认示例 Token。
- Desktop 依赖源码、Node/npm 和固定 5173/8080。
- 50 Token 人工复核、正常协议负对照、签名安装包和 24h Soak 未执行。
